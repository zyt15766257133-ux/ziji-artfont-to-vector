# 透明底文字边缘毛刺修复

日期：2026-10-17。截图中的“透明底”文字可通过内置 `18_transparent.png` 复现。此次修改已加载到本地开发服务 `http://127.0.0.1:8765/`，并通过真实 HTTP 转换接口验证。

## 原因与修改

网页直接显示 SVG；没有发现强制像素化显示的 CSS。原 SVG 路径本身已有台阶与毛刺，因此只修改预览清晰度无法解决。

透明 PNG 中不可见像素的 RGB 可以与文字同色。原单色分支将它当成背景，得到前景／背景色差为零而退出；随后轮廓分支在二值掩膜上拟合，丢失源 alpha 的抗锯齿覆盖率。

`app/pipeline/direct.py` 现在对纯色透明底文字独立判断颜色，从原始 alpha 提取 50% 覆盖率边界，使用 4 倍线性插值定位亚像素轮廓，并去除小于一像素的提取台阶后拟合。透明字使用更紧的几何误差容差；继续核验节点预算和局部拓扑。半透明填充、宽柔边和多色素材退出该纯色捷径，继续由原效果管线处理。

`app/pipeline/svgutil.py` 同时修正“全部顶点是角点时又全部开启平滑”的逻辑，避免矩形弯边。

本次未接入 PolyFit；这些改动修复了现有管线中的具体问题。此前调研报告中相关源码缺陷描述是修复前的记录。

## 同素材完整调用结果

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 边缘区域 alpha 平均绝对误差，0～1，越小越好 | 0.10435 | 0.04527 |
| SVG 总节点 | 785 | 416 |
| 前景掩膜 IoU | 0.9835 | 0.9878 |

误差评估范围为原始透明度边界附近的 17,697 个像素，比较输出回渲后的透明度与几何对齐原图。只有这一张内置样本的数据，不能外推到全部艺术字。它衡量边缘还原误差，不是“清晰度提高百分比”。

对照图：`eval/results/edge_diagnosis/fixed/before_after.png`。

原图、修复前／后 SVG、回渲 PNG、逐项指标保存在 `eval/results/edge_diagnosis/`。复现脚本是 `eval/edge_diagnosis.py`，已有 baseline 不允许覆盖。

## 验证

- 新增 4 项回归均通过：真实透明底样本的边缘覆盖率；透明区 RGB 不影响形状及内孔；半透明填充和柔边不会被误当实色字；全角点矩形保直保角。
- 完整测试：98 项通过，1 项失败。失败为 `tests/test_source_constraints.py::test_compact_brush_is_rejected_when_local_texture_is_lost`，在修改前代码中也复现；MuPDF 报 stitching function 子函数过多，测试读取不存在的 texture 字段。此次未修改或放宽该测试。
- 本地服务重载后 build 为 `805d635d0e66`。实际 HTTP 请求 `/api/sample/18_transparent.png/convert` 返回 `cached=false`、`source_coverage=true`、416 节点、IoU 0.9878；单次完整转换约 587ms。计时只代表本次样本与当前机器。

页面刷新后需重新点击转换；历史记录中的 SVG 是旧结果，不会被自动重写。
