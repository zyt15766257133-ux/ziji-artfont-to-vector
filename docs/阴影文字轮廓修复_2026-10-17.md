# 阴影文字轮廓修复与验证

本次使用截图对应的本地原始样本 `samples/images/12_shadow.png`，没有对截图中的劣化结果再描摹，也没有换字体重打。保留了工作区原有的未提交修改。以下数字均为本机实际运行结果，不代表所有艺术字或商业产品的效果。

## 问题和实现

原流程把字身抗锯齿边缘、灰色阴影一起分色，随后进行碎片清理及节点压缩。结果是字身边缘被切掉、像素台阶变成角点，四层灰色阴影又经过固定模糊。这些步骤叠加，造成截图中的削薄、毛刺和不自然投影。

新增 `shadow_model.py` 为满足条件的平面单色阴影字建立候选：从原始 RGB 估计背景和墨色，拟合投影的水平/垂直偏移、模糊半径及不透明度，再反解字身覆盖率。字身与阴影分别输出；字身没有模糊滤镜，阴影才使用 Gaussian blur。所有参数从输入像素求得，代码不读取样本名称、文字内容、字体或生成样本时的阴影参数。

`direct.py` 新增的可选几何模式利用覆盖率梯度，将前景像素中心投影到 50% 等值边界。原先直接连接像素中心会系统性缩小外轮廓、放大内孔，这是细字“瘦一圈”的一个原因。本次没有使用全局膨胀或锐化掩盖错误。

`geometry.py` 按较稳定的角点分段，均匀弧长采样后拟合；尖角允许两侧切线不同，光滑递归分段共享切线，使用重参数化减少采样偏差。长直段保留为线段；只有原像素支持、且偏移小于约 0.25 像素时才做水平/竖直吸附。真实斜笔画不强制拉正。拟合误差是采样残差约束，并非连续曲线的严格 Hausdorff 上界。

候选必须通过重渲染检查：字身面积、边界覆盖率误差、交并比、孔洞/连通关系、合成颜色误差和节点预算。失败即回到已有管线。多色、纹理、透明底、阶梯阴影、关闭平滑、专色等不适用情况不会强行套用该模型。

同时修正评分的透明度语义：对有滤镜、背景均匀且原图不透明的图片，在原背景上合成输出，对双方使用相同 RGB 色距阈值（>20）。半透明黑色阴影不再因 alpha<50% 被误算为缺失。原 alpha 口径仍保存在 `alpha_shape_iou`，`comparison_basis` 标记新口径；验收条目说明同步修改。透明底素材保持原来的 alpha 口径。

## 同图前后结果

均衡档；完整转换调用，包含预处理、矢量化、指标、预览。指标脚本：`eval/shadow_quality.py`。色彩误差比较原图与白底合成结果，不使用内部拟合得出的覆盖率作独立真值。

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 深色字身面积 / 原图同阈值面积 | 94.53% | 100.29% |
| 深色字身 IoU | 91.97% | 98.14% |
| 字身边缘 RGB 平均绝对误差（0～255） | 25.07 | 5.92 |
| 可见区域 RGB 平均绝对误差（0～255） | 12.10 | 2.87 |
| SVG 锚点，含阴影 | 1878 | 804 |

深色字身采用平均 RGB<80 的统一判据；边缘带为原图该掩膜的 5×5 膨胀减腐蚀。面积比例不等于每一笔的宽度误差，也不能替代局部目检。此样本边缘误差下降约 76.4%，节点减少约 57.2%。

完整调用时间多次观察约 1.4～1.9 秒；实际网页调用为 1735ms。不包含 HTTP 传输及下载导出。最终网页显示：可见轮廓 IoU 98.0%、特征诊断 98.3%、平均 201 节点/字、直线偏离 0.027px。它们是诊断值，不能当作视觉效果的统一百分比。

高质量、均衡、精简三个预设均进入新分支；锚点分别为 1272、804、572。高质量偏向更紧贴输入，均衡节点更少；不是节点越多视觉上就一定越好。

## 验证与边界

- 原图、修复前后 SVG/PNG、四倍细节、JSON 和网页截图在 `eval/results/shadow_quality/`。
- 对全部 25 张内置素材运行新旧完整管线：本样本改变，其余 24 张 SVG 字符串完全相同。后续直线细化仅影响新增几何模式，本样本重新验证，其他样本不进入此模式。
- 新增 6 项测试：独立 SVG 真值的正向/反向/垂直投影，面积及孔洞，模式开关与多色回退，目标样本，以及透明度评分。全部通过。
- 全套测试最终为 **104 通过、1 失败**。失败为既有 `test_compact_brush_is_rejected_when_local_texture_is_lost`：缺少 `comparison['texture']`，同时 MuPDF 报 `too many sub-functions in stitching function`。关闭新增阴影分支仍单独复现；未修改该无关失败或放宽断言。
- PDF 导出回渲：1 页、0 个嵌入位图、220 个绘图对象；相对同背景 SVG 回渲的全图 RGB 平均误差约 1.75/255。PDF 柔影由透明矢量层近似；Illustrator 实际编辑未验证。
- 本地 `127.0.0.1:8765` 服务已重启，HTTP 和网页均确认使用新分支。网页“建议更换素材”来自原样本裁切前主体仅占 13.1%，不是此次轮廓修复失败；该既有提示保留。
- 当前改进主要针对干净背景上的单色字身与同色系柔影。彩色阴影、叠加多重阴影、复杂材质、严重 JPEG 损伤仍需另外验证。原图的真实细节不可能通过平滑无限恢复。

## 搜索并核实的现有方法

2026-10-17 通过浏览器搜索并读取以下一手页面：

1. [Potrace 官方手册](https://potrace.sourceforge.net/potrace.1.html)：明确区分角点阈值 `alphamax` 和曲线合并误差 `opttolerance`；也说明粗糙二值化会丢细节，建议先缩放、插值再阈值。本次采用保留灰度覆盖率、单独识别角点的原则，没有声称集成 Potrace。
2. [Vectorizer.AI 官方说明](https://vectorizer.ai/)：Sub-Pixel Precision 使用抗锯齿值定位边界；Clean Corners、切线匹配、曲线修整、图元拟合分别处理。内部模型闭源；本次没有上传图片、没有获取其同图结果，也不宣称达到或超过商业服务。
3. [PolyFit 作者项目页，SIGGRAPH 2020](https://www.cs.ubc.ca/labs/imager/tr/2020/ClipArtVectorization/)：粗多边形用于判断曲线图元结构，最终仍拟合栅格边界。借鉴“结构判断与最终贴合分开”的方法，没有把本地实现称为完整 PolyFit 复现，也未运行工作区的 PolyFit C++ 工程。
