# 艺术字图片转矢量的已有方案与公开数据

调研日期 2026-10-17。结论基于本项目代码、原始 `xuqiu.docx`、官方产品页面及下列项目文档。论文作者的结果不等于本机复现结果。

## 项目定位

本项目把 PNG/JPG/WEBP 中的艺术字还原成可编辑 SVG，并导出 PDF、PDF 兼容 AI 和部分 EPS。主链路是前景提取、颜色分层、几何轮廓拟合、节点预算、拓扑检查和导出。已经包含 vtracer 和可选 Vectorizer.AI API 适配器。当前源码没有神经网络权重或模型训练入口。

需求除了形状相似，还包含飞白和内孔保留、单字 50～500 节点、渐变与阴影、颜色误差、单张约 5 秒、批量以及按字可编辑分组。因此，单独训练分割网络或让大模型输出 SVG 都不能证明完整需求达标。

## 已有方案

| 方案 | 已经做的事情 | 对当前项目的意义 |
|---|---|---|
| [Vectorizer.AI](https://vectorizer.ai/) | 图片转换为 SVG/PDF/EPS/DXF；官方介绍包含深度学习、完整几何形状拟合、角点优化和亚像素边界 | 可用作效果比较或用户主动选择的付费服务；训练数据为私有；其 FAQ 明确禁止把服务输出用于机器学习训练 |
| [Vector Magic](https://vectormagic.com/) | 在线与桌面位图描摹，在线 SVG/EPS/PDF，桌面另支持 AI/DXF | 成熟商业替代方案；不提供可训练的公开模型 |
| [vtracer](https://github.com/visioncortex/vtracer) | 开源彩色位图矢量化 | 项目已经使用；升级、参数与几何后处理仍值得比较，新增训练不是唯一改进方式 |
| [DiffVG](https://github.com/BachiLi/diffvg) | 可微分 SVG 渲染与逐图路径优化 | 可作为研究底座；不代表已有通用中文艺术字模型 |
| [LIVE](https://github.com/Picsart-AI-Research/LIVE-Layerwise-Image-Vectorization) | 逐层、逐图优化矢量表示，官方实现基于 DiffVG | 可以做图像专属优化，未在这里复现；官方旧环境涉及 CUDA/GCC，不能据此承诺 Windows 下 5 秒完成 |
| [DeepVecFont-v2](https://github.com/yizhiwang96/deepvecfont-v2) | 少量参考字形合成整套矢量字体，包含中文 | 适合字体结构/风格研究；其任务与任意带阴影艺术字图片恢复有区别 |
| [StarVector](https://github.com/joanrod/star-vector) | 图像或文本生成 SVG，提供 1B/8B 模型和 SVG-Bench | 可作未来 GPU 实验；公开指标主要是 SVG-Bench，不能推导出中文笔画、单字节点及本项目验收达标 |

“图片转矢量”已经有成熟市场和多年研究。这个项目可体现价值的方向是本地部署、中文艺术字专门处理、受约束的编辑质量和批量工作流。要比较算法优劣，应固定独立素材和相同节点、颜色、时间约束。

## 公开数据

| 数据来源 | 官方说明的规模/内容 | 适用性与限制 | 本次使用 |
|---|---|---|---|
| [Google Fonts](https://github.com/google/fonts) | TTF/OTF 字体，字形轮廓可精确转 SVG 并渲染 | 本次选 8 个均附 OFL 1.1 的中文字体目录，适合构造有准确轮廓的配对样本；不能代表真实飞白、多层阴影和所有品牌字标 | 已下载，保留授权、提交 SHA 和文件 SHA256；实际生成并训练 |
| [DeepVecFont-v2 数据](https://github.com/yizhiwang96/deepvecfont-v2#dataset) | 官方提供 OneDrive/百度网盘，包含中文/英文字集、字体及预处理数据 | 官方 Font Copyrights 明确写中文字体来自方正，未经许可不能商用；本次只核对说明，没有下载该数据或复现其模型 | 作为研究参考 |
| [SVG-Fonts](https://huggingface.co/datasets/starvector/svg-fonts) | StarVector README 列训练约 180 万、验证 9.15 万、测试 4800；数据卡字段 `Filename`/`Svg` | 适合字形 SVG 序列学习；此次读到的数据卡没有明确填写 license，不能据代码 Apache 2.0 推断数据可商用；也不能确认覆盖本项目中文风格 | 作为研究参考 |
| [SVG-Stack](https://huggingface.co/datasets/starvector/svg-stack) | StarVector README 列训练约 210 万；包含多种 SVG 图元 | 通用图标/设计图形为主，可用于图像到 SVG；需另外核对样本来源与数据授权 | 作为研究参考 |
| [Make Me a Hanzi](https://github.com/skishore/makemeahanzi) | 9000 多个简繁汉字，笔顺与笔画矢量数据 | 适合结构、笔画分解；`dictionary.txt` 与 `graphics.txt` 来源授权不同，需分别看 COPYING；艺术字风格有限 | 作为研究参考 |

规模数字来自官方项目文档，不是此次实际下载量。公开可下载、代码开源与数据可商用是三个需要分别核对的问题。

本次没有找到并核验一套能直接覆盖“中文艺术字位图、干净分层 SVG、飞白、渐变、阴影、按字语义与节点限制”的完整公开训练集。字体轮廓合成配对数据是可立即运行、标签可靠的起点。后续提高完整产品质量，需要真实业务样本及人工核验的矢量真值。

## 本次训练范围

训练一个小型残差 U-Net，学习单字前景覆盖率；输入是由边界估计背景得到的色差、局部亮度差等固定特征。目标是提高单色中文字符在噪声、纸纹、压缩和不均匀背景上的提取能力。预测掩膜通过项目现有的 `direct.fit_mask_paths` 拟合为单色可编辑 SVG。

它不是 DeepVecFont/StarVector 的复现，也不是直接生成 SVG 的大模型。没有使用商业矢量化服务输出当训练标签。网络的测试分数只说明该前景任务的效果，完整矢量验收需另外评估。现有 Web/API 入口保持原调用方式，实验通过 `python -m ml.infer` 使用。

来源快照在 `sources/`，字体原件与 OFL 授权在 `../data/fonts/`，运行环境锁在 `../environment-lock.txt`。训练结果和适用边界另见 `../README.md` 及 `../runs/baseline_v1/`。
